# Worksheet for a project architecture brief

Use one copy per system or independently governed capability. Fill it with the sponsor, designer and a person who uses or operates the outcome. Replace bracketed prompts with project facts, or record an owner and date for a material unknown. One page is often enough to decide what evidence to collect next.

## Mission and boundary

| Field | Project entry |
| --- | --- |
| System, date and owner | [Stable system name, planning horizon, accountable role] |
| Mission and beneficiary | [Who can do what, under what conditions, and how they know it succeeded] |
| In scope | [People, equipment, procedures, stores and services whose behavior this project controls] |
| External parties | [Neighbor, owner, agreement and what happens when it is unavailable] |
| Operating modes | [Normal, degraded, maintenance and recovery modes that change the promise] |
| Hard limits | [Limit, units, source and authority to change it] |
| First expensive commitment | [Decision, last responsible date and cost of delay or reversal] |

## Tailored scope of the design work

- Working approach and plausible alternative — [what the team could build or operate].
- Views and profiles needed — [reader, question and link for each].
- Evidence to obtain before committing — [method, configuration, owner and due point].
- Deferred concerns — [rationale and condition for revisiting].
- Handoff — [decision authority, implementation owner, operator and stakeholders receiving evidence].

**Read-back check.** Ask the sponsor to confirm the promised outcome, an operator to identify one degraded state, and an implementer to name the first uncertainty that would change their design. If their accounts differ, record the disagreement and its owner. See [a completed framing example](../../examples/field-observations/01-frame/mission-and-options.md).
