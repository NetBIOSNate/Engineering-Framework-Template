# Pilot, implement and improve the framework

A framework is implemented when project teams can use it to make and preserve decisions in their normal workflow. Choose a pilot whose next real decision is still open. Name a sponsor, a steward of the framework and an owner for the pilot decision. Agree when the trial ends and what result would warrant wider adoption.

## Run a bounded pilot

1. Establish a baseline. Select a recent decision and ask an unfamiliar engineer to find its owner, rationale, affected interfaces and outstanding evidence. Record time, missing answers and the cost of resolving them.
2. Choose the smallest applicable profile. Use the brief, one decision and one scenario. Fit records into the project's existing review, requirements and evidence systems. Agree how stable links and permissions will work for the next reviewer.
3. Observe one live review. Note which fields change the decision, which dependent teams receive a usable contract, and where participants maintain the same fact twice.
4. Re-run the retrieval exercise with another reader. Ask an implementer to derive a check from the decision and an operator to find restoration authority. Record failures in the framework itself as improvement items.
5. Refine the vocabulary, example or profile. Publish the change with its rationale and applicability to old records. Test the next edition on a project with a different shape before widening the core.

## Evidence for adoption

Track elapsed time to answer a consequential question, recurring mismatches at interfaces, decisions reopened by missed assumptions and the effort to prepare a review. State how the sample was selected. Document count can show use while giving little evidence of decision quality. A decline in reported risks can signal better design or less disclosure. Pair metrics with a walkthrough of an actual decision.

Introduce a new required record only when a recurring failure, external obligation or significant consequence justifies its cost. Offer a profile-specific field if only a subset of projects needs it. Preserve earlier record semantics by versioning the viewpoint or mapping old names to new concepts. A framework change should identify its steward, affected users, compatible interpretation and review date.
